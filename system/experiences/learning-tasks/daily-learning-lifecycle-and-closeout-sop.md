# 30 天每日研学任务全生命周期与收束标准操作规程（SOP）

## 1. 运行时间守卫规程

1. **正常启动与运行周期**：
   - 每日计划于 Asia/Shanghai 16:00 启动；
   - **研究硬截止**：本次 `run_date` 次日 **15:00:00 CST**；
   - **收束窗口**：**15:00:00 – 16:00:00 CST** 专用于日报整理、交付审计、学分结算、次日提示词编制与 Git 提交推送。
2. **动态时间门判定**：
   - 距 15:00 剩余 $\ge 120$ 分钟：当前问题局部饱和时，可重建候选池，预习恰好一张下一日课程卡（记为 `partial`，不计学分，不推进 `next_day_index`）；
   - 距 15:00 剩余 $90 - 119$ 分钟：继续当前高价值问题或做有边界预览；
   - 距 15:00 剩余 $< 90$ 分钟：严禁打开新来源或新课题，专注于已有推演闭环；
   - **15:00:00 到达**：立即停止一切新课题研究，准时启动收束。

## 2. 大纲五项交付逐项审计规程

在 `curriculum-deliverable-audit-<day>.json` 中执行逐项严格审计，禁止笼统判定：
1. **回忆（Recall）**：检查底层微观机制与模型适用条件；
2. **主线（Mainline）**：检查选定质量区一手原件文献阅读与数据对账；
3. **练习（Exercise）**：检查横向对比矩阵、方法学伪简并与协方差表格；
4. **反证（Falsification）**：检查跨区类比失败的反例与物理停止判据；
5. **交付（Deliverable）**：检查不适用性判据清单与微观动力学工件。

## 3. 学分与里程碑结算不变量

1. **单卡单结原则**：
   - `card-credit-<day>.json` 中仅记录 `formal_completed: [day_index]`；
   - `completed_day_count` 递增 +1，`next_day_index` 递增至次日；
2. **严禁超前授分**：
   - 任何针对次日（Day+1）的预习内容仅允许记录在 `partial_day_indices`，严禁提前发放学分；
3. **次日提示词隔离**：
   - `prompt.md` 只负责准备次日教学大纲，严禁包含任何次日研究结果或提前结项声明。

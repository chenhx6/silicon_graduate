# Markdown 与 LaTeX 约定

- 新写或修订的 GitHub 向文档使用 GFM。行内数学写 `$\alpha + \beta$`，独立数学用单独的 `$$` 开合，前后各留空行。列表内的块公式与所属列表项正文对齐，例如 `- ` 下缩进两个空格。优先选 GitHub、Pandoc、XeLaTeX 都能识别的命令。
- TeX 运算和分组保留单个命令反斜杠及成对分组，例如 `\alpha`、`\beta`、`\rho`、`\approx`、`\text{...}`、`\mathrm{...}`、`\frac{...}{...}`。原生 `.tex` 保留模板已有的数学环境。
- Markdown 表头、分隔行、数据行使用相同的列数。表格的数学绝对值写 `$\lvert x\rvert$`，条件分隔写 `$p(x\mid y)$`。代码单元格中的竖线也要按 GFM 表格转义，例如 `` `x\|y` ``。Obsidian 表格别名采用 `[[目标\|别名]]`。GitHub 向正文使用标准 Markdown 链接。
- 代码示例放入反引号或围栏。GFM 文档中的普通文本在字符会成为 Markdown 语法时才转义。表格内竖线与数学内的下标、百分号分别遵循各自的语法。
- 保存为 UTF-8。Python 生成含 TeX 的 Markdown 时使用原始字符串、正确转义的反斜杠，或读取单独的模板。`r"\a"` 是两个字面字符，普通字符串 `"\a"` 生成 U+0007。正则替换可用返回原始字符串的回调，避免替换器再解释一次反斜杠。
- 维护已有文档时保留有效的历史样式和引文，只有在特定目标渲染失败或本次编辑需要时调整。发现坏公式先保留公式附近的文字、数值、单位和物理关系，再用上下文或原件恢复字符。

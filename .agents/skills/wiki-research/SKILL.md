# Wiki 科研探索与执行

用于已授权的科研探索；用户已有授权持续有效，不因切换研究阶段重复请求批准。
先读项目工作约定和相关知识，再读 `system/workflows/autonomous-research.md` 的当前等级、授权与停止条件。
L0–L4 和问题状态只由该工作流维护；本技能不建立第二套状态、后台任务或发布策略。

## 研究起点

1. 从现有 project、research-note、source 和 handoff 恢复问题、已有认识、失败路线、数据可得性及当前决策目标。原件和外部获取按已有馆藏/归档规则处理。
2. 判断是工程设计还是科研探索。工程需求交给 brainstorm 的工程路径；科研问题优先执行本技能。只有会改变近期动作且上下文无法恢复的信息才询问，其他未知量写为假设并继续可解析部分。
3. 按需参考当前环境的 scientific-brainstorming 或 arbor：前者提供发散/收敛方法，后者仅在多条持续实验路线需要树结构时使用。不可用时使用本地研究卡和现有页面；方法的存在不证明效果。

## 发散、核验与选择

使用 `system/templates/research-card.md`，将有保留价值的研究卡写入既有 canonical 知识页。
先生成不同机制/测量效应/模型边界，再评价；必要时选前提反转或从目标展开替代路径。
单模型连续切换视角如实标为视角切换。真实隔离上下文的生成仍不自动构成独立科学证据。

每个入选候选必须含稳定 ID、机制与前提、最强替代解释、区分性预测、反驳条件、最低成本行动、来源依赖、查新范围和空结果价值。
回查最接近已有工作与反例，记录查询、日期、范围；未找到先例不能升级为首次发现。
按信息增益、可检验性、数据可得性、成本和负结果价值选择下一步；模型分数只辅助排序。

## 执行循环

按 `autonomous-research.md` 的“L3/L4 每轮研究决策与恢复”推进：恢复 -> 假设 -> 选择 -> 执行 -> 核验 -> 修正。
每轮记录为何选这一步、真实动作、证据定位、认识变化、失败约束和下一步；工具成功与完成标记不是研究完成证据。
失败路线保留原因、上层约束与复活条件，不静默删除。达到目标或没有足够信息增益时有理由停止。

固定输入/代码版本和评测规则，区分开发与确认。重复参与选择的材料不称未见确认；改评测器要新建基线。
同源注入恢复不能单独证明物理响应正确；使用独立公式/实现、真实测量和条件相容的参照，分别声明验证范围。
审查者直接读取原件/代码/数据，不能只读执行者筛选摘要；没有独立复核时如实记录 self-audit。

## 保存、核验与交接

科学研究卡、竞争矩阵、失败约束和认识变化保存 `knowledge/`；报告、回执和执行计划保存 `outputs/`；临时发散保存 `tmp/`。
普通问答保持只读。不得为了套用外部技能建立 `docs/plans/`、改变 raw、修改评测原件或启用外部运行器。
已有页面足以保存状态时不新增文件。多轮研究可在原页面附 `research-cycle` JSON 块，显式检查：

```bash
python3 system/scripts/wiki_research_cycle.py --root . knowledge/projects/具体页面.md
```

格式、示例与适用边界见 `knowledge/methods/evidence-driven-research-cycle.md`；本检查只验证记录一致性，不能证明证据真实或结论正确。
中断后回到现有状态、输入身份和未完成动作，避免重复实验；缺口不足以支持结论时保存边界而不制造结果。
需要工程实现时再接 plan/make；原文核验接 wiki-evidence-query/get-paper；科学写回接 ingest/reflect/L3/L4。
固定上游、许可、样本哈希和本地采用决定见 `system/agent-capability-adoption.md` 及 `system/agent-capability-sources/research-cycle-20261127.json`。

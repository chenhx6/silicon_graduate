# 本地文献馆藏

这是智能体内部能力。按用户的自然问题自行检索、消歧和阅读，不要求用户输入命令、
选择检索模式或操作馆藏界面。维护和异常处理见
[馆藏工作流](../../../system/workflows/local-literature-archive.md)。

## 检索与使用

1. 需要找文献、读取原件、查证主张或准备获取时，先查本地；已知 source 或文件路径
   可直接核验。按 DOI/arXiv、题名作者或主题使用
   `system/scripts/local_literature_archive.py` 的 `check-local` / `find` JSON 结果。
   具体参数先读脚本 `--help`；脚本未就绪时如实报告，使用限定范围的路径/文件名、
   source 和 manifest 检索，不能声称已调用索引。
2. 索引缺失、过期或范围不足时，只做必要的 `inventory` / `refresh` 或有界回退；
   缓存更新限于被忽略的 `.agents/local-literature/`，不写 source 或原件。
   已有索引可用时直接查询；仅凭时间流逝不在每次问答重扫全库。出现新增文件、
   路径变化、未覆盖目录或有意义的漏检线索再刷新。
   没有命中只说明本次范围未发现。外部发现新身份后、下载前再次 `check-local`；
   外网 403 或历史获取失败不证明本地无全文。同一任务无新线索不重复空扫描。
3. 仅用已验证属于文献自身的 DOI 建立身份，参考文献中的 DOI 不可合并作品。
   题名近似、同一实验和相同字节分别作为候选、来源依赖和副本关系处理。
   身份冲突保留候选；人工身份 overrides 记录依据，参数以实现为准。
   `unverified-identifier-mention` 只表示首页/文本提到该编号，可能是参考文献；
   检查候选题名和作者后再确认，不能据此当成目标全文，也不能直接忽略候选重新下载。
4. 出版版优先，arXiv 原件保留；已确认是同一作品才聚合版本。区分应采用的出版底本
   与实际本地可读版本。只有预印本时可有界使用，但定位符必须指向该实际版本。
   补充材料与勘误随主文献返回，勘误保留自己的书目身份；修正只应用于其适用部分。
   `canonical_edition: published` 不证明本地文件就是出版版。若存在版本未判定的本地
   PDF，先读其首页和source中的版本说明，确认后记录带 `basis` 的路径级消歧，
   再刷新首选原件；不要求用户选择版本。
5. 实际使用前核对身份、路径、可读性和 SHA-256。目录命中、元数据、摘要或首页
   提取不证明全文可用或已读。按需用可选 `index-text --path` 提取指定原件全文；
   默认只提取本地元数据与 PDF 前几页，不做 OCR 或全库 embedding。

结果供智能体判断时应保留匹配依据、实际路径/版本、可用性、检索范围、附件/纠错关系
和已有 source/阅读范围。面向用户只呈现与问题相关的结论、证据链接和实际版本边界。
`stats` 的文件、作品、附件、source 关联等维度分开解释；不能据此计算阅读完成率。

## 与研究流程衔接

- 本地不足时转 [文献访问](../../../system/workflows/literature-access.md)，沿用现有
  获取器；此 skill 不修改 get-paper。取得材料后按
  [research-archive](../../../system/workflows/research-archive.md) 留档并刷新目录。
- 学习记录只读关联 `knowledge/sources/`；登记、下载和全文索引均不自动建立 source、
  生成 citation key、提升 `reading_depth` 或改变 `Covered scope`。
- 需要书目导出时按 [Zotero 约定](../../../system/zotero-integration.md) 使用既有脚本；
  不手改生成 BibTeX，不写用户 inbox。目录与索引不作为论文事实源，也不扩展 QMD 范围。
- 路径异常先报告；历史 54 项可恢复材料与另一个历史手稿版本缺口只按工作流中的
  专项修复处理，不因每次查询自动复制 raw、改 source 或重跑全库恢复。
